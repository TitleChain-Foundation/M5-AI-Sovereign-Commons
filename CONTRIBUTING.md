# Contributing

This project is a Draft for Public Comment. Criticism, competing designs, test
cases, and implementation evidence are welcome.

## Before opening an issue or pull request

- State whether the proposal is normative text, an example, an implementation,
  provider configuration, research, or a deployment report.
- Identify the authority, privacy, security, interoperability, and migration
  effects.
- Cite dated primary sources for provider-specific claims.
- Add or update tests for executable behavior.
- Do not claim provider endorsement, M5 enrollment, certification, or legal
  status without authoritative evidence.

## Never submit

- credentials, tokens, secrets, or production connection details;
- personal or private M5POD evidence;
- confidential M5Canon rules;
- proprietary material you are not authorized to publish;
- regulated personal, financial, health, biometric, or neural data;
- generated classifications presented as legal conclusions.

Suspected vulnerabilities and unpatched exploit details must be reported
privately as described in [SECURITY.md](SECURITY.md), not through an issue, pull
request, or Discussion.

General participation and documentation questions may be sent to
[support@titlechainfoundation.org](mailto:support@titlechainfoundation.org).
Do not send vulnerability details, credentials, private evidence, or production
information to the support address.

## Contribution licensing

The licensing structure is described in [LICENSE.md](LICENSE.md) and
[LEGAL-NOTICES.md](LEGAL-NOTICES.md). By submitting a contribution, a
contributor represents that they have the right to submit it and agrees that it
may be distributed under the license assigned to its destination path.
